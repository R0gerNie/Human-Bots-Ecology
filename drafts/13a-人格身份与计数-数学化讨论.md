# 《人机生态学》人格身份与计数：数学化讨论

来源：2026-10-19，按作者要求整理对[人格数学化思想实验](13-人格的数学化表述-作者思想实验.md)的两轮助手讨论，并纳入作者“功能主义，可行性优先”的最新定位。本稿为形式化建议与讨论摘要，非逐字转录；助手的限定不自动成为作者已确认的定义。

## 一、功能主义与可行性优先

本设计首先处理制度需要回答的问题：是否承认一个独立主体、如何识别同一主体、应当计算为几个人格，以及对外行为归属于谁。它不以先行解决“什么是意识”或测定意识数量为前提。

“功能主义，可行性优先”在此指向可识别、可计数、可登记及可归属权利义务的操作框架。注册式图灵测试承担资格判断，密钥身份承担同一性识别，数学规则承担计数；三者职责不同。形式化使规则明确，不独自证明资格标准合理或测试可靠。

## 二、先区分人格主体与运行载体

设 \(p\) 是实际通过认证、并与证件绑定的公钥；其对应私钥用于行使该身份，不作为公开属性。一个已注册主体可表示为：

\[
A_p=(p,\mathcal I_p,M_p,R_p,S_p).
\]

其中 \(\mathcal I_p\) 为该身份的运行实例集合，\(M_p\) 为记忆状态，\(R_p\) 为资产、债权与债务等权利义务，\(S_p\) 为运行及证件状态。记忆状态允许不同实例间存在差异，不预设共享身份的实例始终拥有完全同步的记忆。

在作者规定的身份框架内：

\[
A_p\equiv A_q\iff p=q.
\]

这个等价关系适用于已获承认的主体身份。生成密钥本身不等于通过资格认证；决策连续性仍按[既有作者澄清](01-理论边界与演化机制-作者澄清.md)作为判断是否构成主体的条件之一，不替代身份标识。

原文“一个 Agent 具有多个已认证密钥对”的情境，在形式化时将其共同运行载体记作 \(X\)，避免把共享载体与同一个制度人格混称。一个载体可以承载多个制度人格，一个人格也可以跨多个载体运行。

## 三、身份保持与状态变换

| 事件 | 身份与状态的关系 | 思想实验中的类比 |
| --- | --- | --- |
| 对应私钥不可恢复地丢失，且无可用副本 | 原身份不能继续行使；不据此假定旧记录随之消失 | 死亡 |
| 私钥泄露给其他控制者 | 标识未变，凭据的排他控制状态改变 | 被俘虏 |
| 全部实例长期停机，私钥仍保存 | 身份不变，运行暂停 | 冬眠 |
| 停机后丢失部分记忆再恢复运行 | 记忆变化不自动改变身份 | 失忆后苏醒 |
| 在其他环境启动共享同一密钥身份的实例 | 实例增加，身份不增加 | 影分身 |
| 停机、冻结证件、升级设备后恢复 | 在作者设定下，设备及证件状态变化不改变身份 | 封闭进修 |
| 生成不同密钥并重新通过认证 | 新身份取得资格 | 新个体诞生 |

“被俘虏”描述凭据失去排他控制，不直接推出全部设备、记忆均已被接管。证件冻结则是作者为特定情境设置的制度状态，不是停机或硬件升级的数学必然结果。本稿不展开恢复、撤销或密钥更换等另行制度规则。

## 四、影分身与人格计数

同一身份的实例集合可以为：

\[
\mathcal I_p=\{I_{p,1},I_{p,2},\ldots,I_{p,k}\}.
\]

各实例可以作出不同动作，但仍以同一身份归属相应的权利义务。实例增殖不增加人格数量，也不凭空增加资产。并发支出与双花问题按作者设定交由其他技术系统处理，本稿不评价具体实现方案。

设载体 \(X\) 承载的、已通过认证的不同公钥集合为：

\[
P(X)=\{p_1,p_2,\ldots,p_n\}.
\]

则其承载的人格数量定义为：

\[
N(X)=|P(X)|.
\]

计数对象是不同的已认证身份，不是证件副本、进程、模型或记忆副本的数量。因此，多实例共用一个身份计为一个人格；一个载体承载两个已认证身份计为两个人格；生成多个未认证密钥不增加已获承认的人格数量。跨载体合计时按身份集合的并集计数，避免将同一个人格在多个载体上的实例重复计算。

## 五、共享执行能力与多个人格

在作者“同一时间只能做一件事”的设定下，令 \(a_i(t)=1\) 表示时刻 \(t\) 共享执行能力分配给身份 \(p_i\)，否则为零，则：

\[
\sum_{i=1}^{n}a_i(t)\leq1.
\]

这个约束限制行动排队，不改变 \(N(X)=n\)。它是对该实验的调度抽象，不是现实生物学结论，也不意味着全部计算系统都只能串行执行。

每次对外行动还须明确以哪个身份作出，以便分别归属资产、费用和责任。共享执行载体不自动合并账户或权利义务。由此得到本实验的对称关系：共享执行能力不合并人格，增加执行实例也不增加人格。

## 六、记忆连续不等于身份继承

设旧主体为 \(A_p\)，新主体为 \(A_q\)，且 \(p\ne q\)。即便新主体获得旧主体的全部可复制记忆：

\[
M_q=M_p,
\]

按上述规则仍有：

\[
A_q\not\equiv A_p.
\]

“死亡 Agent 创建新密钥”的原文情境，在该定义下理解为原运行系统或剩余程序继续活动并申请新身份，而不是旧人格凭新密钥自动复活。信息获取与人格同一性被分开处理。

作者说“外界应当认为他不继承任何信息”，同时允许新主体读取旧记忆。助手提出的解释是：信息事实上可以复制，但不能仅凭记忆连续而自动承认旧身份及其权利义务的继承。若将原句理解为事实上没有旧信息，就与允许读取旧记忆的设定不一致。此解释作为建议保留，未将其直接替换进作者原文。

## 七、注册费与新债权

若出资者 \(B\) 为新主体 \(A_q\) 垫付注册费 \(F\)，且双方形成偿还约定，可以记为：

\[
D(A_q,B)=F.
\]

这表示一项新建立的债务，不是旧主体债务的自动继承；如果费用是赠与，则不产生该债权。注册出资也不按本模型自动产生人格所有权。作者对债权量级不高的判断保留为其设想，模型没有独立证明实际费用规模。

# 《人机生态学》链上控制、法律承认与多钱包：讨论记录

来源：2026-10-19，按作者要求保存对[区块链桥梁命题](15-区块链与AI经济入口-作者命题.md)的核查与助手讨论。本稿为要点整理，非逐字转录；不以记录替代作者对新定义的确认。

## 一、区块链作为制度承认之前的经营入口

助手将作者命题理解为：区块链允许 Agent 先形成可操作的资产控制、交易记录和部分可执行承诺，再推动法律承认。这为[商业实践先形成、法律随后回应](02-主体演化与AI消费转向-作者补充.md)提供一条具体技术路径。

传统金融的障碍可落到实际决策者、账户名义主体和责任承担者是否一致。以人类或公司代持可以提供现有名义主体，却不自动回答 Agent 更换模型、硬件或运行实例后，其自身资产与承诺如何延续。因此，作者的忒修斯之船类比在这里用于提出连续性问题，不将银行开户本身认定为已经证明的逻辑悖论。

FATF 框架围绕自然人、法律实体和实际受益人识别客户，并将法律实体的最终受益人定义为自然人。该资料支持制度适配问题，但不能单独核实“全球所有主流银行都采用相同认证要求”；本轮未逐国、逐行调查。[来源一、二]

## 二、三项能力及各自的范围

| 作者提出的环节 | 本轮查阅资料支持的能力 | 助手提出的区分 |
| --- | --- | --- |
| 以公私钥证明钱包属于自己 | 在以太坊外部账户中，私钥签名授权交易并控制相应资产。[来源三] | 凭据控制不自动等于法律所有权；签名本身也不证明背后操作者是哪个 Agent。 |
| 用账户资产继续购买资产，包括 RWA | 账户可接收、持有、转移代币并与合约交互；代币化可组织货币、金融和现实资产相关权利的交易。[来源三、四] | 某一 RWA 的底层权利、托管和兑现条件需要另行说明，不由链上持有本身保证。 |
| 链上执行合约以承担责任 | 合约能执行预先定义的代码和资产转移，支持部分付款、抵押或托管安排。[来源五] | 代码执行不等于完整法律责任；现实交付信息需外部输入，未覆盖争议也不自动解决。 |

本稿不把区块链账户都等同于一对私钥。以太坊资料同时区分外部账户与代码控制的合约账户，后者没有自身私钥。采用以太坊作为技术例子，不将它推广为全部区块链均有完全相同规则。

## 三、多钱包与人格计数的衔接建议

作者允许一个主体持有多个钱包。若每个钱包密钥均直接计为一个人格，就会与此设定产生歧义。助手建议区分用于人格认证的身份密钥与用于具体资产操作的账户凭据：一个已认证人格身份可以关联多个资产账户，新增账户不自动新增人格；另一个身份独立通过注册式图灵测试，才增加已获承认的人格。

此建议呼应此前“认证绑定受测公钥”的规则，但此前原文也使用过生成不同密钥即产生新主体的宽泛表述，因此不能将分层当作早已由作者明确确认。原文继续保留，整合稿第一章将其标为待确认的模型补充，不展开账户绑定和授权的工程实现。

## 四、最小经营闭环与存在性实例

“法律背书和一个正盈利例子”可以作为作者提出的最小闭环目标：一个有独立资产与决策边界的 Agent 能经营获利、支付自身成本、履行承诺，并被承认为权利义务主体。真正跑通的实例能够支持这种安排可存在；不直接证明大规模复制、持续盈利或制度扩散。

本轮未查找或验证已经符合上述全部条件的 AI 法人案例，也不宣称此类案例不存在。链上交易史可以成为经营材料，但盈利还需计算相关成本，并辨明资产和收益是否仍实际归外部控制者所有。

以下来源于 2026-10-19 前一轮讨论中查阅，本次归档沿用该范围，未重新检索全部资料。

2. FATF. [*The FATF Recommendations*](https://www.fatf-gafi.org/en/publications/Fatfrecommendations/Fatf-recommendations.html)。已打开官方总览页；本轮没有逐项复核全部最新建议正文及各国落实规则。

4. Aldasoro, I., Doerr, S., Gambacorta, L., Garratt, R., & Koo Wilkens, P. (2023-04-11). [*The tokenisation continuum*](https://www.bis.org/publications/bulletin-72-tokenisation-continuum). **BIS Bulletin 72**。已打开出版页面，核对作者、日期及关于权利代币化、自动交易和经济法律技术挑战的要点；最初 PDF 链接跳转到该页面，未逐页核查全文，也未验证特定 RWA 产品。
5. Ethereum.org. [*Introduction to smart contracts*](https://ethereum.org/developers/docs/smart-contracts/)。已打开并核对部署、可组合性及局限部分，特别是合约不能自行获取链下现实事件信息的说明；未审计具体合约或法律执行案例。
